# Стайлгайд backend

## Структура модуля NestJS

```text
apps/api/src/modules/listings/
  listings.module.ts
  api/            контроллеры, DTO запросов и ответов, маппинг в DTO
  application/    сервисы сценариев (use cases): CreateListing, HideListing
  domain/         сущности, value objects, доменные ошибки и события, без зависимостей от Nest и Prisma
  infra/          репозитории на Prisma, клиенты внешних систем
  listings.events.ts
  __tests__/
```

- Контроллер только принимает запрос, валидирует и вызывает сервис сценария. Логики в контроллерах нет.
- Доменный слой не импортирует NestJS, Prisma и другие модули.
- Другие модули используют только то, что экспортирует `listings.module.ts`.

## TypeScript

- `strict: true`, без `any`. Если тип неизвестен — `unknown` и сужение.
- Именование: классы и типы — PascalCase, функции и переменные — camelCase, константы — UPPER_SNAKE_CASE, файлы — kebab-case (`create-listing.service.ts`).
- Ошибки домена — свои классы (`ListingNotFoundError`), фильтр исключений переводит их в Problem Details.
- Даты — только `Date` в UTC. Деньги — `bigint` или value object `Money`, никаких `number` с дробной частью.
- Импорты: сначала внешние пакеты, затем `@clickauto/*`, затем относительные. Порядок поддерживает ESLint.
- Форматирование — Prettier, правила — ESLint из `packages/config`. CI падает на ошибках линтера.

## Валидация

- Схемы запросов — Zod из `packages/shared`, одни и те же на фронте и бэке.
- Все входные данные валидируются на границе (контроллер, обработчик очереди, ответ парсера).

## База данных

- Таблицы и колонки — snake_case, таблицы во множественном числе: `listings`, `car_details`.
- Первичные ключи — `uuid` v7. Внешние ключи — `<entity>_id` с индексом.
- У каждой таблицы `created_at` и `updated_at` (timestamptz).
- Удаление — мягкое (`removed_at`) для объявлений и пользователей, жёсткое — для технических данных.
- Миграции — только через Prisma Migrate, одна миграция на одно изменение, миграции не редактируются после попадания в основную ветку.
- Миграции обратно совместимы: сначала добавить колонку, задеплоить код, потом удалить старую.
- Сиды справочников (марки, модели, категории, регионы) лежат в `packages/db/seeds` и версионируются.

## Очереди и воркер

- Одна очередь на тип задачи: `import.999md`, `import.makler`, `import.klaxon`, `rates.daily`, `search.index`, `email.send`.
- Обработчики идемпотентны: повтор задачи не создаёт дублей.
- Ретраи с экспоненциальной задержкой, после последней попытки задача уходит в dead-letter-очередь и создаёт алерт.

## Логирование

- JSON-логи через pino. Обязательные поля: `level`, `time`, `traceId`, `module`, `msg`.
- Персональные данные (email, телефон, текст сообщений) в логи не пишем. Если нужно — маскируем.
- Уровни: `error` — нужна реакция, `warn` — подозрительно, `info` — бизнес-события, `debug` — только локально.

## Тесты

| Уровень | Что | Инструмент |
| --- | --- | --- |
| Юнит | Доменная логика, value objects, маппинг импорта | Vitest |
| Интеграционные | Сервисы с реальными PostgreSQL, Redis и Meilisearch | Vitest + Testcontainers |
| API | Контракты эндпоинтов, коды ошибок | Supertest |
| Парсеры | Адаптеры источников на сохранённых HTML-снимках | Vitest + фикстуры |

- Новый сценарий — минимум один интеграционный тест на успешный путь и один на ошибку.
- Покрытие доменного слоя — от 80%.
