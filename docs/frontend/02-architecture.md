# Архитектура frontend

Сайт — приложение `apps/web` на Next.js App Router. Публичные страницы (каталог, карточки, профили) рендерятся на сервере ради SEO и скорости. Личные разделы (профиль, чат, форма объявления) — клиентские, за авторизацией.

## Структура папок

Слои по упрощённому Feature-Sliced Design: импортировать можно только из слоёв ниже.

```text
apps/web/src/
  app/                    маршруты Next.js, layout'ы, metadata, только сборка страниц
    [locale]/
      (public)/           каталог, карточки, профили — SSR
      (account)/          профиль, мои объявления, избранное, чат — нужна сессия
      (auth)/             вход и регистрация
  widgets/                крупные блоки страниц: шапка, лента, панель фильтров, галерея
  features/               действия пользователя: add-to-favorites, send-message, apply-filters, publish-listing
  entities/               доменные сущности для UI: listing, user, conversation, category — карточки, бейджи, форматтеры
  shared/
    api/                  generated/ (orval), http-client.ts (mutator), query-client.ts
    ui/                   реэкспорт и сайтовые обёртки над packages/ui (дизайн-система общая с админкой)
    lib/                  утилиты: деньги, даты, склонения, аналитика
    config/               константы, env
    i18n/                 словари ru.json, ro.json
```

Правило зависимостей: `app → widgets → features → entities → shared`. Импорт вверх или между соседями одного слоя запрещён (проверяет ESLint).

## Маршруты

Локаль — первый сегмент URL: `/ru/...` и `/ro/...`. У каждой страницы есть `hreflang` на другую локаль.

| Маршрут | Страница | Рендеринг |
| --- | --- | --- |
| `/[locale]` | Главная | SSR + кэш |
| `/[locale]/cars` | Лента авто, фильтры в query | SSR |
| `/[locale]/cars/[brand]/[model]` | Лента по марке и модели (SEO-посадочные) | SSR + кэш |
| `/[locale]/cars/item/[id]-[slug]` | Карточка авто | SSR + кэш с ревалидацией |
| `/[locale]/goods`, `/[locale]/goods/[category]` | Товары для авто | SSR |
| `/[locale]/goods/item/[id]-[slug]` | Карточка товара | SSR + кэш |
| `/[locale]/services`, `/[locale]/services/[category]` | Услуги | SSR |
| `/[locale]/services/item/[id]-[slug]` | Карточка услуги | SSR + кэш |
| `/[locale]/u/[username]` | Публичный профиль | SSR |
| `/[locale]/login`, `/[locale]/login/code`, `/[locale]/signup/profile` | Вход, код, ник и имя | Клиент |
| `/[locale]/me`, `/[locale]/me/listings`, `/[locale]/me/favorites`, `/[locale]/me/settings` | Личный кабинет | Клиент, `noindex` |
| `/[locale]/me/listings/new`, `/[locale]/me/listings/[id]/edit` | Форма объявления | Клиент, `noindex` |
| `/[locale]/chat`, `/[locale]/chat/[conversationId]` | Чаты | Клиент, `noindex` |
| `/[locale]/swipe` | Тиндер для машин (следующий этап) | Клиент |

## Данные

- Все запросы к API — через клиент, сгенерированный orval, и TanStack Query. Подробно — [API-клиент](06-api-client.md).
- Публичные страницы предзагружают данные на сервере (`prefetchQuery` + `HydrationBoundary`), клиент получает готовый кэш без повторного запроса.
- HTML публичных страниц кэшируется Next.js (`revalidate` и теги). После изменения объявления API вызывает ревалидацию по тегу `listing:<id>`.
- Ключи запросов — только сгенерированные `get<Operation>QueryKey`, руками не пишутся.
- Сессия: httpOnly cookie, Next.js middleware проверяет её наличие для `(account)` и делает редирект на вход.
- Фильтры и сортировка — только в URL (nuqs). Панель фильтров меняет URL, лента читает URL. Нет второго источника правды.
- Лента — бесконечная прокрутка с курсором и кнопкой «Показать ещё» как запасным вариантом для поисковиков.

## Фильтры

- Конфигурация фильтров приходит из API: список полей, их тип и значения, зависимости (марка → модель → поколение, категория → атрибуты). Фронт рендерит панель по конфигурации, а не хардкодит поля.
- Смена марки сбрасывает модель и поколение, смена категории — её атрибуты (по [правилам из аналитики](../analytics/05-filters.md#зависимости-фильтров)).
- Регион по умолчанию: при первом визите запросить геолокацию, определить ближайший город через API, записать в cookie. Выбор вручную перезаписывает cookie.
- На телефоне фильтры открываются полноэкранным листом (Sheet) с кнопкой «Показать N объявлений», на десктопе — боковая панель.

## Интернационализация

- Словари `ru.json` и `ro.json`, ключи по фичам: `listing.price.negotiable`, `auth.code.invalid`.
- Тексты ошибок API выбираются по `code` из ответа, а не по `detail`.
- Числа, даты и валюты — через `Intl` с локалью пользователя. Цена всегда в валюте автора объявления.
- Справочники (марки, категории, регионы) приходят с бэка уже на нужном языке.

## Чат

- Socket.IO-подключение открывается после входа и живёт в провайдере на уровне `(account)` layout'а.
- Отправка оптимистичная: сообщение сразу в списке со статусом «отправляется», подтверждается событием `message:new` с тем же `clientId`.
- История подгружается через REST с курсором при прокрутке вверх.

## Производительность

| Метрика (мобильные, p75) | Цель |
| --- | --- |
| LCP | ≤ 2,5 с |
| INP | ≤ 200 мс |
| CLS | ≤ 0,1 |
| JS на первой загрузке карточки | ≤ 170 КБ gzip |

- Фото — через `next/image` и imgproxy: WebP/AVIF, `srcset` под ширину экрана, первое фото галереи с `priority`.
- Тяжёлые блоки (чат, форма объявления, свайпы) — динамический импорт.
- Lighthouse CI в пайплайне падает при выходе за цели.

## SEO

- `generateMetadata` на каждой публичной странице: title, description, Open Graph с первым фото.
- Микроразметка JSON-LD: `Car` / `Product` + `Offer` для карточек, `BreadcrumbList`.
- `sitemap.xml` генерируется по активным объявлениям, справочникам марок и категорий.
- Скрытые и снятые объявления отдают 410, страницы кабинета — `noindex`.
