# Правила для AI-агентов

Этот файл читают AI-агенты (Claude Code, Codex, Cursor и др.), которые работают в репозитории ClickAuto. Правила обязательны. Если правило мешает задаче — остановись и спроси человека, а не обходи его.

## Проект

ClickAuto — mobile-first сайт для покупки и продажи авто, товаров для авто и услуг в ПМР и Молдове. Монорепозиторий: сайт (`apps/web`), админка (`apps/admin`), API (`apps/api`), воркер (`apps/worker`), общие пакеты (`packages/*`).

## Ключевые решения (не менять без согласования)

- Сайт mobile-first, не нативное приложение. Языки RU и RO, локаль в URL.
- Вход только по одноразовому коду на email или через Google. Паролей, входа по телефону, Telegram и Apple нет.
- При регистрации обязательны ник (вводит сам пользователь) и имя, фото — нет. Онбординга нет.
- Ролей у клиентов нет: любой пользователь и покупает, и размещает авто, товары и услуги. Дилеров и отдельных кабинетов на первом этапе нет. Роли `moderator` и `admin` — только для сотрудников в админке.
- Цену автор указывает в рублях ПМР, леях, USD или EUR. Показываем её всегда в валюте автора. Пересчёт по курсам ПРБ и НБМ — только для фильтра и сортировки.
- Деньги хранятся целыми числами в минимальных единицах. `float` для денег запрещён.
- Регион по умолчанию — по геолокации. Темы светлая и тёмная.
- Справочник марок и моделей ведём сами. VIN не проверяем, только даём скопировать.
- Объявления импортируются с 999.md, makler.md, klaxon.md; контакты продавца показываем, фото копируем к себе.
- Монетизации на первом этапе нет.

## Как работать

1. **Сначала план.** Для задачи больше одного файла кратко опиши план до правок.
2. **Маленькие изменения.** Одна задача — одно логическое изменение. Не делай попутный рефакторинг, о котором не просили.
3. **Документация вместе с кодом.** Меняешь API, доменную модель, фильтры или поведение продукта — обнови соответствующий документ в `docs/` в том же изменении.
4. **Новое решение — в документы.** Если человек принял продуктовое или техническое решение в разговоре, внеси его в нужный документ и закрой вопрос в [открытых вопросах](docs/analytics/07-open-questions.md).
5. **Проверяй перед тем, как сказать «готово».** Линтер, типы и тесты затронутых пакетов должны проходить. Если что-то не запускал или упало — так и скажи.
6. **Не выдумывай.** Не придумывай эндпоинты, поля, бизнес-правила и значения справочников. Нет ответа в документах — спроси.

## Код

- TypeScript `strict`, без `any`. Валидация — схемы Zod из `packages/shared`, общие для фронта и бэка.
- Backend — NestJS, модульный монолит. Модуль ходит в другой только через его публичный сервис, не в чужие таблицы. Логика — в `application/` и `domain/`, не в контроллерах.
- Frontend — Next.js App Router, слои `app → widgets → features → entities → shared`, импорт только вниз. Серверные компоненты по умолчанию.
- Стили — Tailwind и токены из `packages/ui`. Произвольные значения вроде `w-[37px]` и цвета в обход токенов запрещены.
- Тексты интерфейса — только через ключи i18n, в обоих словарях `ru.json` и `ro.json` сразу.
- Новые события аналитики — сначала в [схему метрик](docs/analytics/06-metrics.md), потом в код.

## Сгенерированный код и API

- `apps/*/src/**/api/generated` создаёт orval. Не редактируй эти файлы руками.
- Порядок изменения API: контроллер и DTO в `apps/api` → `pnpm --filter api api:openapi` → `pnpm --filter web api:generate` (и `admin`, если затронуто) → код фронта. Всё в одном изменении.
- У каждой операции API должен быть стабильный `operationId` и тег. Эндпоинты админки — только под `/api/v1/admin` с тегом `admin-*`.
- На фронте не вызывай `fetch` напрямую — только сгенерированные хуки TanStack Query.

## База данных

- Схема меняется только миграцией Prisma. Не правь уже применённые миграции.
- Миграции обратно совместимы: добавить → задеплоить код → удалить старое.
- Не запускай миграции и сиды на staging или production — это делает человек или CI.

## Безопасность

- Не коммить секреты, токены, `.env`. Новые переменные окружения добавляй в `.env.example` с описанием.
- Персональные данные (email, телефоны, тексты сообщений) не пишем в логи, тесты и фикстуры. В фикстурах — только выдуманные данные.
- Каждый эндпоинт админки проверяет роль, каждое изменяющее действие пишется в журнал `AdminAuditLog`.
- Не отключай проверки (ESLint, типы, тесты, хуки) ради того, чтобы что-то прошло.

## Git

- Схема веток и релизов — [gitflow](docs/gitflow.md). Задачи делаются в `feature/<КОД-ЗАДАЧИ>-<кратко-что-делаем>` от `develop`, хотфиксы — в `hotfix/...` от `main`. Прямые коммиты в `main` и `develop` запрещены.
- Если код задачи неизвестен — спроси у человека, не придумывай его.
- Коммиты — Conventional Commits: `feat(listings): hide listing from search`, `fix(auth): resend code limit`, `docs(analytics): add services section`.
- Не коммить, не пушь, не создавай PR и не трогай удалённые ветки без явной просьбы человека. Никогда не делай force push в общие ветки.
